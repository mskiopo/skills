# 中文博客写作

写作目的是**自我反思和学习**，不是面向读者的宣发。文章应该像一份"写给自己、也顺便分享"的复盘笔记：冷静、实在、真诚，不端着，也不博眼球。

## 一、语气与视角（底线）

- **第一人称"我"** 的立场，是"我做了什么、我错在哪、我学到了什么"，不是"你可以这样做""如果你遇到"这种面向读者的说教。但**行文上要弱化"我"这个字**，别满屏"我"。
- **弱化"我"字的写法**：把"我用了 / 我写了 / 我加了 / 我发现"这类"我 + 动词"，改成无主语或隐含主语的客观表达。例："我用 `GetPosition` 拿坐标" → "用 `GetPosition` 拿坐标"；"我写了个诊断脚本" → "写了个诊断脚本"；"我发现" → "发现" / "排查下来"。句子既通顺，也不堆"我"。
- 不搞对话式、不搞"聪明的朋友跟你聊天"那一套，也不要写成营销文案或官腔。
- 有观点、有态度，但**克制、不张扬**。可以自嘲，但不卖惨，也不装。
- 少用"你"，除非确有需要。主体是"我"的反思。
- **涉及他人（用户、同事）时，用那个人的视角如实复述，别用"我"的视角转述。** 举例：用户口误把"右键"说成"左键"，正解是"用户最初说的是"左键…"，但一路问下来，用户真正说的是"右键…""；错解是"一开始我以为…，后来我才搞清楚用户要的是…"。后一种写法把重点歪到了"我怎么猜的"，前一种才还原了"用户实际怎么回事"。复盘的重点是事实和教训，不是"我感知的波折"。

## 二、内容取舍（什么写、什么不写）

- **写**：有学习价值的踩坑、机制澄清、方法论沉淀——这些才是复盘的价值所在。
- **个人的失误，用一条标准判断**：**它能不能提炼出普适的经验？**
  - 能提炼出普适经验（比如 token 别硬编码，哪怕是我自己埋的坑），就写，而且如实写"这是我自己的错误"。
  - 纯属一时手滑、且说不出任何可迁移教训的（漏看报错、随手写错一个值），才不写。
- **琐碎、无普适价值、且自己已经承认过的问题，不写。** 比如一句口误、一个已经当面认下的判断失误，搬上来既不体面也没价值。写复盘不是写流水账，别把每件小事都记一笔。

## 三、总体结构（先复盘，再提炼）

1. **先简单复盘错误 / 过程**：我当时遇到了什么、怎么排查的、错在哪。
2. **再做经验提炼**：从这些坑里总结出可复用的经验，放在复盘之后，作为沉淀。

> 顺序是"复盘在前、经验在后"，而不是一上来就摆一堆结论教别人。

## 四、开头（2-3 句内解决）

- **直接进入正事**：说清楚这次要复盘的是什么（一个故障、一个功能、一次踩坑）。
- **遇到技术项目，开头或近开头处给一句项目背景 + 技术栈**（前端/后端/数据库等），让读者知道这是在什么环境里发生的，但别铺陈太长。
- **不写"元评论"**：不要在正文里解释"我为什么写这段""这类问题该不该写"这种作者视角的自我说明，直接写内容本身。
- 可以平实，不必制造悬念。
- 禁止这类套话开场："随着 XX 的不断发展""在当今这个时代""今天我们来聊聊""本文旨在 / 本文将探讨"。
- 不要从背景、历史、定义慢慢铺陈。

## 五、可读性 / 可扫读性（重点）

- **一段只讲一件事。** 一段里出现两个意思就拆成两段。短段落没问题，单独一句成段用来强调也没问题。
- **转折就换行。** 遇到"但是 / 然而 / 其实 / 可惜 / 更糟的是"这种转折，另起一段。
- **长短句交替。** 别连续三个长句；偶尔来个短句压一下节奏。
- **尽量别用破折号（——）。** 改用逗号、句号，或者换行。
- **善用小标题和列表。** 留好路标，让内容可扫读。
- 保留技术细节（代码、命令、报错原文），别为了"好看"删干货。
- **加粗要有重点，别乱加**：在关键步骤里，加粗那些真正重要的内容（排查的结论、复盘的关键动作、教训的落点），方便复盘和扫读。但不要给普通词（"分类""之前""表头名"这类）随手加粗——到处加粗等于没有重点。
- **删多余的引入句。** 像"回头看这一整天，几条能复用""下面我来讲讲""先说结论"这类没有信息量的过渡，直接删掉，让内容自己说话。

## 六、用词红线（禁用空话）

禁止出现、以及这些词的同类替换：

- 赋能、闭环、抓手、颗粒度、底层逻辑、顶层设计
- 极致、无缝、引领、颠覆、赋能式
- 内卷式堆砌的形容词（"深入浅出地""全方位地""多层次地"）
- 废话过渡句："值得注意的是""总的来说""不难发现""众所周知"

**替换原则**：能说人话就别说术语；非用术语不可，先花半句话解释一下再用。

## 七、结尾

- 收得干脆，落在"这次我学到什么、下次会怎么做"。
- 禁止"综上所述 / 总而言之"式收尾。
- 不要突然升华、拔高、喊口号。

## 八、标题

- **写完正文再定标题**。
- 取标题的"中间地带"：
  - 不要**太张扬**（悬念体、危言耸听、博眼球的营销腔）。
  - 也不要**太正式**（"XX 项目：一次 XX 实录/总结"这种公文腔）。
  - 取"具体、平实、点出主题"的一档，比如"前端联调排障的复盘""给系统加字段踩的几个坑"。

## 写作流程

1. 让我先一句话说清楚：这篇文章**要复盘的核心是什么**（说不清就先别写）。
2. 列大纲：先复盘过程/错误，再提炼经验。
3. 逐节写：我做了什么 → 错在哪 → 学到了什么。
4. 写完全文再定标题。
5. 通读一遍，检查："有没有说教腔、有没有空话、有没有过度张扬？"
